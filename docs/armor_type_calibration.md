# 大小装甲板、原点与标定核验

## 确认的原车事实

A `ArmorDetector.cpp::Judge_Type` 用两灯中心距离/平均灯条高度，阈值 2.8。
俯视会压缩图像中的高度，这个二维比值不等于真实长宽比。
A `ArmorSolver.cpp::Slover` 的半尺寸 SMALL=(.065,.025) m、LARGE=(.115,.025) m，本次保持 130×50 / 230×50 mm。
A `text.yaml:Transform` 的平移是 [-.05,-.05,0] m。本次没有再叠加任何「约5厘米」经验偏移。

C 模型采用局部 yz 平面，四角顺序为 TL/TR/BR/BL；A Legacy 的局部 xy 平面和角点序列不相同。
新 Solver 与 C 的四角定义配套，仅调整真实尺寸，不能交换模型尺寸或原点来补偿角点错误。

## 新判定流程

1. YOLO 的颜色、数字和大小输出作为类型先验。绝不先用 A 的 2.8 阈值覆盖它。
2. 对两种物理尺寸分别做 PnP，在原车同步姿态下按同济甲板倾角假设重投影，比较平均像素误差。
3. 另一种合法类型只有在误差同时减少超过 `type_min_error_margin_px`，且误差比小于 `type_max_error_ratio` 时才覆盖先验。当前为 1 px / 0.6，属于待录像标定的算法阈值，不是实物测量结果。
4. 最终类型必须满足 A 实际编译路径的类别过滤；之后检测、PnP、Tracker 共用同一个 Armor.type。关联时也比较 name/type。

原车 CMake 没有定义 SENTRY，故保留其非 SENTRY 分支：普通模式排除 outpost/base；BIG 不接受 sentry/3/4；SMALL 不接受 1/base；前哨模式仅接受 SMALL outpost。
没有复制同济 Decider 中「不打工程/5号」规则去改变原车策略。
C YOLO11 表把数字1标为 small；在 Adapter 中明确按英雄语义修正为 BIG，再应用原车过滤。数字1没有被删除。
对于被先验误标为禁用类型的候选，不会仅因为禁用就自动换另一类型，仍要求几何误差的优势判据。

## 已执行与不能推断的结果

合成场景使用真实 A 内参/畸变/外参和原车尺寸，包含正视、俯视约34°/52°以及两种物理尺寸。
测试从错误 BIG 先验恢复合成 SMALL，同时保留合成 BIG；SMALL/BIG PnP 的 3D 回投误差门限为3 mm，yaw 门限0.03 rad。
这些是确定性合成检验，不是实车测距精度或分类准确率。

同济 demo.avi 前200帧产生147项检测，均输出 sentry SMALL 先验，缺少人工大小标注和原车姿态。
其中5项的同济 ratio 超过2.8，仍保持 SMALL 先验；该 ratio 使用长灯条长度，与 A 的平均高度定义也不同，不能把这5项直接当作原车误判修复数。
预览和原始 CSV 在 rebuild_validation 中。不宣称147项均正确，没有编造准确率。
该片段没有真实 BIG 样本，因此真实 BIG 分类、多角度假设消歧及距离精度尚未验证。

## 需要补齐的数据

- 同一已测量 SMALL/BIG 目标，在原车镜头、分辨率、曝光下采集正视、俯视、仰视、滚转及远近距离序列。
- 录像须带逐帧原车姿态、颜色、模式、时间戳；记录 RGB 写入方式，防止把存储通道顺序误当 BGR。
- 人工标注 name、type、四角、遮挡及不可判帧；逐类别/角度统计混淆矩阵、拒识、类型切换次数及3D误差。
- 核验甲板倾角是否符合 C 的普通 +15°/前哨 -15°假设；不符合时当前双模型残差不足以决定尺寸，应先修正模型假设。
- 用标定板/实物核验 R 的方向、t 的原点、镜头分辨率与内参绑定；不能用调整尺寸或加5厘米平移掩盖标定错误。
